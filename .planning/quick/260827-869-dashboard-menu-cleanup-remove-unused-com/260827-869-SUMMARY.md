# Quick Task 260827-869: Dashboard menu cleanup + Settings consolidation + profile/header identity sync + password change Summary

**One-liner:** Removed the TailAdmin demo nav (Components showcase, Calendar) with all 20 orphaned files, unified Settings into one flat sidebar section (Storage/SEO/Backup/Newsletter admin-gated + Profile for all roles), threaded the real session identity through the header (avatar via next/image or initials fallback, router.refresh on profile save), and shipped a tested self-service password change (Zod gate + digest-mapped INVALID_PASSWORD + revokeOtherSessions) on the profile page.

## What Was Done

### Task 1 — Sidebar restructure (commit c34281d)

- `navItems` reduced to Posts / Categories / Tags / Media / Pages / Users (admin) / Subscribers (admin). Settings parent-with-submenu, standalone Profile, and Calendar entries removed.
- New flat `settingsItems` array (visibleSettingsItems derivation renamed consistently): Storage → `/dashboard/settings/storage`, SEO → `/dashboard/settings/seo`, Backup → `/dashboard/settings/backup`, Newsletter → `/dashboard/settings/newsletter` (all `requiredRole: "admin"`), then Profile → `/dashboard/profile` with NO role gate (D-09). Per-item history comments preserved (Plan 04-05, 05-03, 08-04, 260824-3l2).
- Second group heading renamed "Reference" → "Settings"; collapsed-state HorizontaLDots behavior untouched; submenu machinery, hasRole filter, and auto-open effect untouched.
- Icons reassigned within the existing import set (PlugInIcon → Storage, PageIcon → SEO, BoxIcon → Backup, ListIcon → Newsletter, UserIcon → Profile); CalenderIcon + TableIcon imports dropped.
- Header comment block rewritten: showcase/Calendar notes removed as superseded by the owner request; D-05 UX-only role-filter and D-01 /dashboard/* notes kept accurate.
- Deleted (grep-verified zero live importers first): 7 (ui-elements) pages, dashboard/calendar page, `components/calendar/`, `components/example/`, `components/ui/video/` (both files — YouTubeEmbed's only importer was VideosExample), `components/ui/images/`, `components/common/ComponentCard.tsx`. Shared `components/ui/{alert,avatar,badge,button,modal}` and PageBreadCrumb untouched.

### Task 2 — Header identity sync (commit 9a4cf01)

- `(admin)/layout.tsx` AuthGate now derives `headerUser { name, email, avatar }` exactly like `dashboard/profile/page.tsx` (avatar via the additionalFields cast) and passes it to AdminShell alongside `role`.
- `AdminShell` → `AppHeader` → `UserDropdown` prop chain (all serializable values).
- `UserDropdown`: all hardcoded TailAdmin demo identity removed. Avatar: non-empty string → next/image 44×44 rounded-full (imageUrlSchema contract — same as ProfileForm renders); null/empty → rounded-full brand-toned (bg-brand-500) initials tile (first letters of the first two name words, uppercased, "?" fallback). The three demo entries that all pointed at /dashboard/profile collapsed into a single "Edit profile" DropdownItem; Sign out link byte-identical to before.
- `ProfileForm` onSuccess: `router.refresh()` added alongside the existing `invalidateQueries` — the server-rendered (admin) layout re-fetches the session so the header thumb/name update immediately after a save.

### Task 3 — Self-service password change (TDD; commits c718df3 RED, 0521515 GREEN)

- RED first: four behavior tests added to `users.test.ts` (changePasswordMock added to the vi.hoisted harness + flat auth.api mock). Verified failing 4/43 before any implementation existed.
- `users-schema.ts`: `changePasswordSchema` (currentPassword min 1 / max 128; newPassword min 8 / max 128 — mirrors Better Auth's default minPasswordLength), `CHANGE_PASSWORD_DIGESTS` { INVALID_PASSWORD, CHANGE_FAILED }, `CHANGE_PASSWORD_ERROR_MESSAGES` map (friendly copy, CR-02).
- `users.ts` `changeOwnPassword`: (1) `getSessionOrThrow()` FIRST — self-service for any signed-in role, NO requireCan, no userId parameter so it can never target another user (T-Q-869-01); (2) safeParse → INVALID_INPUT; (3) `auth.api.changePassword({ headers: await headers(), body: { currentPassword, newPassword, revokeOtherSessions: true } })` — headers forwarded per the 260824-qtu rule (verified: the endpoint is gated by sensitiveSessionMiddleware → getAuthoritativeSessionFromCtx, headerless internal calls 401); (4) endpoint rejection mapped: `err.body?.code === "INVALID_PASSWORD"` → digest INVALID_PASSWORD, anything else → CHANGE_FAILED; raw APIError never rethrown; `log.info("password changed")` only after resolution (T-Q-04).
- `PasswordForm.tsx` (new client component): RHF + zodResolver + non-optimistic TanStack useMutation; three password fields with autoComplete current-password / new-password; local superRefine schema adds confirmPassword-must-match and new-must-differ-from-current; error banner maps `err.digest` via CHANGE_PASSWORD_ERROR_MESSAGES with CHANGE_FAILED fallback (UsersTable pattern); success banner "Password updated."; fields reset() on success so passwords don't linger in the DOM; identical INPUT_CLASS/banner markup to ProfileForm.
- `profile/page.tsx`: second card "Change password" below the profile card with the other-devices-signed-out hint; no props (action self-resolves the session).
