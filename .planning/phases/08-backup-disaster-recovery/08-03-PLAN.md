<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Google consent → app callback | OAuth redirect crosses from Google back to the app's /api/auth/google/callback |
| App → Google Drive API | Backup dumps cross to Google Drive using the stored refresh token |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-03 | Spoofing / Tampering | OAuth callback CSRF | high | mitigate | state param (random, session/cookie-bound) verified on callback before any token exchange; mismatched state → 400 + no exchange. (RESEARCH Security Domain V3; google-callback.test.ts Case 2) |
| T-08-03b | Information Disclosure | refresh-token storage | high | mitigate | refresh token encrypted via lib/crypto AES-256-GCM before upsert to backup.gdrive_creds; never returned to the client (redact on read in 08-04). (D-03) |
| T-08-03c | Elevation of Privilege | Drive scope | medium | mitigate | drive.file scope (app-created files only) — NOT the full "drive" scope. Test asserts the over-privileged scope string is absent. |
| T-08-03d | Spoofing | refresh-token loss on re-auth | medium | mitigate | prompt:consent + access_type:offline ALWAYS passed (RESEARCH Pitfall 4) so a refresh_token returns on every consent. |
| T-08-SC | Tampering | googleapis npm install | high | mitigate | googleapis verified OK (official googleapis/google-api-nodejs-client repo, 9.8M/wk, 13 yrs, no postinstall) per RESEARCH Package Legitimacy Audit — no blocking human checkpoint required. (D-02 deliberate trade-off) |
</threat_model>
