<objective>
R2 backup destination + R2 media-object sync (full disaster-recovery slice). Adds the Cloudflare R2 backup destination — a DEDICATED S3Client pointed at a DEDICATED backup bucket (NOT the media bucket/client) — and wires `syncMediaBucket` into `runBackupJob` so a backup covers the Postgres DB AND the actual media image files. After this plan, an admin-enabled R2 destination receives dump files + media objects, and a restored site has its images intact.

Purpose: Closes D-06 (full DR = DB + R2 media). RESEARCH Anti-Pattern: the backup R2 bucket/client MUST be distinct from the media R2 bucket/client — reusing `getActiveProvider()`/`s3Client` would point at the media bucket with media creds. This plan implements that separation.

Output: r2.ts destination + media-sync.ts + job.ts media-sync wiring + 2 Wave 0 tests.
</objective>

| Media R2 bucket (source) → backup destinations | Media objects are read from the media bucket and copied to each enabled destination |
