<objective>
Close the Phase 2 UAT Test 5 MAJOR issue (AUTH-07): a non-admin user created via the dashboard never receives the verification email — Resend shows no send attempt at all.

Root cause (diagnosed in .planning/debug/createuser-no-verify-email.md — diagnosis complete, do not re-investigate): better-auth 1.6.23's admin-plugin createUser endpoint contains NO email-verification logic; emailVerification.sendOnSignUp:true is consumed at exactly two sites in the whole library — /sign-up/email and OAuth link-account. The dashboard path (UserDrawer → createUser action → auth.api.createUser) therefore never invokes the configured sendVerificationEmail callback. The comment at src/lib/auth/index.ts:73 asserting otherwise is a false docs-memory assumption, and the D2 automated coverage never exercised the framework path: __tests__/email-flows.test.ts mocks betterAuth as an identity function, mocks the admin plugin as a no-op, then calls the configured callback directly — it proved config wiring, never behavior.

Purpose: (1) Make the send explicit — after a successful creation the createUser action itself calls auth.api.sendVerificationEmail; a send failure must not mask the successful creation. (2) Remove the false claim from the code. (3) Close the test blind spot with an action-layer regression test that proves the causal link — the config-only assertion pattern that shipped this bug can no longer stand in for behavior coverage.

Output: A surgical four-file fix — src/actions/users.ts (explicit send), src/lib/auth/index.ts (comment correction), src/actions/__tests__/users.test.ts (regression tests), __tests__/email-flows.test.ts (honest test naming). No new files, no new packages, no refactors, no UI changes (UserDrawer needs none — the send is server-side).
</objective>
