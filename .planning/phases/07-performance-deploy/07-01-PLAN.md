## Phase Goal

**As a** blog founder, **I want to** push to main and have Coolify build a verified, leak-free production image, **so that** the non-negotiable performance/security bar is enforced automatically with zero CI/staging overhead.

<objective>
Build-pipeline slice (PERF-02 + PERF-06 scaffolding): the multi-stage Dockerfile with two build-step gates (ESLint `--max-warnings 0` + gzipped bundle < 100KB), the bundle-size gate script, and the `.dockerignore`. This is the load-bearing safety net for the no-staging/no-CI deploy model (D-31/D-32).

Purpose: Because a push to main deploys directly to production (D-32), the Docker build stage is the only place to catch (a) TailAdmin/editor JS leaking into the public chunk and (b) cross-group imports from `(site)` to `(admin)`. This plan produces the gate machinery; Plan 07-04 runs the actual Coolify deploy against it.

Output: Dockerfile, .dockerignore, scripts/check-bundle-size.mjs, package.json `check-bundle` script.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer laptop → Coolify build | A `git push origin main` crosses this boundary; Coolify clones the repo and runs the Dockerfile build stages with no human in the loop. |
| Build stage → Runtime image | Runtime secrets (DB, auth, email, S3, encryption, Redis) must NOT cross this boundary — they are injected by Coolify env at container start, never baked into image layers. |
| Runner container → External network | The non-root `nextjs` user has no privilege to escalate; the standalone server binds to `0.0.0.0:3000` behind Coolify's proxy. |

## STRIDE Threat Register (ASVS Level 1 — block on `high`)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01-SC | Tampering | Docker base image + pnpm install | high | mitigate | Pin to `node:20-alpine` official image; `pnpm install --offline --frozen-lockfile` from committed lockfile — no floating dependency resolution, no install-time tampering surface. |
| T-07-01-01 | Information Disclosure | Dockerfile ARG/ENV layers | high | mitigate | Only `NEXT_PUBLIC_*` vars appear as `ARG`/`ENV` (D-21). All runtime secrets injected via Coolify env at runtime. Negative-grep acceptance criterion enforces: `grep -E "^(ARG\|ENV) (DATABASE_URL\|BETTER_AUTH_SECRET\|...)"` returns zero matches. |
| T-07-01-02 | Elevation of Privilege | Runner container | medium | mitigate | Runner stage creates non-root `nextjs:nodejs` user (UID/GID 1001) and sets `USER nextjs` before `CMD`. ASVS V5 default-deny. |
| T-07-01-03 | Tampering | Build pipeline integrity | high | mitigate | Two gates run inside the builder stage: (1) `pnpm lint --max-warnings 0` catches any cross-group import via the existing `no-restricted-imports` rule (D-12/D-15), (2) `check-bundle-size.mjs` catches catastrophic public-chunk bloat > 100KB gzipped (D-13/D-14). Either gate failing aborts the deploy — this is the SOLE pre-production safety net (D-31/D-32). |
</threat_model>
