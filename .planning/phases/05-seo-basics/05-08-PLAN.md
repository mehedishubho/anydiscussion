Close the final open gap in 05-UAT.md ("The post edit page renders, and the Schedule picker persists picked dates" — R1 re-test blocker):

The edit page is a Server Component that passes an inline no-op handler function as a prop to the 'use client' SchedulePicker. Functions cannot cross the server-to-client RSC serialization boundary, so EVERY visit to /dashboard/posts/[id]/edit throws (surfaced via error.tsx; the "error url" in the user's toast is the Next.js docs link embedded in the message). The bug is Phase-3 code first live-load-tested by the R1 re-run — publish itself succeeded; only the post-publish visit to the edit page crashed.

Second half of the same gap: even before the crash, the picker was decorative. SchedulePicker declares that handler prop REQUIRED (which forced the server stub), consumes it only inside its flatpickr config, and nothing persists the picked date — setSchedule(postId, publishedAt) exists at actions/posts.ts:391 (permission-gated, unit-tested, D-15) with ZERO call sites.

Fix: delete the stub prop from the edit page, remove the prop from the component interface entirely, and call setSchedule directly from the client component's flatpickr onChange option with sonner toasts matching the 05-06 dashboard pattern. Clear-to-empty semantics: ignore (guard clause) — setSchedule requires a non-null Date and flatpickr's default readonly input means a UI clear is not reachable; the persisted value simply stays. One deliberate 3-line addition beyond the strict missing[] list: hide the picker card from authors (role already sits in scope from 05-06) — Phase 3 D-15 makes setSchedule editor/admin-only, so without the hide, authors get a control whose every use ends in a FORBIDDEN error toast. Same UX-only-gating pattern as 05-06's Publish button; the action remains the authority.

Purpose: the R1 re-test becomes completable end-to-end (edit page loads, schedule persists) — which is the live verification path for the sitemap/RSS entries (SEO-02/SEO-07 chain this gap-closure series has been unblocking since 05-06).
Output: renderable edit page, functioning persisted Schedule picker with toast feedback, and a structural regression test that would have caught this bug class in Phase 3.
